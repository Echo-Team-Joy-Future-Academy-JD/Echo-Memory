4. Common workflows

Train one memory row (from repo root):

bash train/memory_baselines_basic/run_spatial_memory_baseline.sh
# or context:
bash train/context_learning/run_pre_qkv_ctx20.sh

Smoke eval with a HF checkpoint:

huggingface-cli download Echo-Team/Echo-Memory \
  spatial_mem/epoch-0.safetensors --local-dir ./ckpts
export CKPT=./ckpts/spatial_mem/epoch-0.safetensors
bash eval/v2/run_static_consistency_loop_and_revisit.sh

Keep the row folder name in CKPT so runtime picks the correct memory profile.

5. Cursor vibe coding

Use Cursor Agent (Composer) for multi-file changes. Tips tuned for Echo-Memory:

  • Scope prompts — name the memory family, script, and eval branch (replay / in-domain / open-domain).
  • Point to entry scripts — e.g. run_spatial_memory_baseline.sh, eval/v2/run_basic_replay_gt.sh.
  • Rules — add .cursor/rules/echo-memory.mdc with pool naming (Static in-domain pool, Dynamic training pool), public doc constraints, and path env vars.
  • Skills — Cursor skills such as create-rule, create-skill, babysit (CI/PR loops) help repeat release tasks.
  • Ask mode — use for reading diffsynth/ or tracing checkpoint → config without edits.

Example prompts

Add a smoke test script that downloads context_k1 from
Echo-Team/Echo-Memory and runs eval/v2/run_basic_replay_gt.sh
with DATASET_BASE_PATH pointing at the static in-domain pool.

Trace how env/memory_baseline_runtime.py maps spatial_mem
checkpoints to inject flags — summarize in doc/checkpoints.md.

Public repo hygiene: never commit upload bash, internal benchmark names, or machine-local paths. WeChat QR lives on the project page & README only — not here.

5. Cursor 协作编程

用 Cursor Agent（Composer）做多文件改动。Echo-Memory 建议：

  • 明确范围 — 写清 memory 家族、脚本、评测分支（replay / in-domain / open-domain）。
  • 指向入口脚本 — 如 run_spatial_memory_baseline.sh、eval/v2/run_basic_replay_gt.sh。
  • Rules — 在 .cursor/rules/echo-memory.mdc 写池命名（Static in-domain pool、Dynamic training pool）、公开文档约束与环境变量。
  • Skills — Cursor 的 create-rule、create-skill、babysit（CI/PR 循环）适合重复发布任务。
  • Ask 模式 — 阅读 diffsynth/ 或追踪 checkpoint → 配置，不改代码时使用。

示例 Prompt

添加 smoke test：从 Echo-Team/Echo-Memory 下载 context_k1，
用 static in-domain pool 跑 eval/v2/run_basic_replay_gt.sh。

追踪 env/memory_baseline_runtime.py 如何把 spatial_mem
权重映射到 inject 标志，并在 doc/checkpoints.md 摘要说明。

公开仓库规范： 勿提交上传脚本、内部 benchmark 名、本机路径。微信群二维码仅在项目页与 README — 不在本指南。

6. Site & release (maintainers)

After editing docs/index.html, docs/style.css, or docs/i18n*.js:

bash scripts/publish_gh_pages.sh

HF weights: update via Hugging Face UI or hf upload (maintainers only). Upload scripts stay local — not in GitHub.

Bilingual project page: strings in docs/i18n.js, runtime in docs/i18n-runtime.js.

6. 站点与发布（维护者）

修改 docs/index.html、docs/style.css 或 docs/i18n*.js 后：

bash scripts/publish_gh_pages.sh

HF 权重：网页或 hf upload 更新（仅维护者）；上传脚本保留在本地，不进 GitHub。

项目页双语：docs/i18n.js 文案，docs/i18n-runtime.js 切换逻辑。

7. Checklist

  • Smoke eval with one HF checkpoint before tagging a release.
  • doc/checkpoints.md matches HF folder names.
  • Public docs use Echo pool names — no internal paths or benchmark codenames.
  • Run publish_gh_pages.sh after site changes; spot-check EN/中文 on the live page.

7. 检查清单

  • 发版前用至少一个 HF 权重跑 smoke eval。
  • doc/checkpoints.md 与 HF 目录名一致。
  • 公开文档使用 Echo 池命名 — 无内部路径或 benchmark 代号。
  • 改站点后运行 publish_gh_pages.sh，检查线上 EN/中文。
