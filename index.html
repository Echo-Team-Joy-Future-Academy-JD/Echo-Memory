Echo-Memory
A Controlled Study of Memory in Action World Models

When the camera leaves and returns, which memory keeps the same world instead of a plausible but different scene?

01 · Overview

One backbone, one protocol — only memory changes.

Echo-Memory fixes the action-to-video stack and varies only how history is stored and read back. Replay, in-domain loop closure, and open-domain return are reported together.

02 · Memory Design

Context · Compression · Spatial · State-Space

Four memory families share a write–read interface; only capacity and representation differ.

Context

Raw history windows at K = 1, 5, or 20 chunks.

Compression

Learned compact tokens at compression ratio r = 4.

Spatial

Explicit read/write spatial state across chunks.

State-Space

Block-wise SSM memory for long-horizon carry.

03 · Evaluation

Replay · In-domain revisit · Open-domain return

Three branches probe replay fidelity, loop closure, and identity under edited returns.

Replay

PSNR, SSIM, and LPIPS on chunk-wise reconstruction.

In-domain

180° loop closure with VLM-assisted scoring.

Open-domain

Edited first frames plus 45° return probes.

04 · Qualitative Evidence

Return probes expose identity drift.

Side-by-side panels compare memory variants on revisit and open-domain return.

05 · Main Conclusions

Replay quality ≠ memory quality.

Rankings shift from replay metrics to return probes — replay alone is not the final memory score.

  • Raw context scales open-domain return more than replay.
  • Compact memory can drop identity on return.
  • Block-wise SSM strongest open-domain return in our matrix.
